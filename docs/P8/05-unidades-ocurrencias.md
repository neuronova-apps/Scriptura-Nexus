# P8.2.3. Unidades textuales y ocurrencias

Base main 39db4e9943cda2a57e226de493cdcbbac1e2a059. P8.2.2 integrada y despliegue confirmado por el responsable. Solo Gen y Dan, versión fija OSHB v.2.2. Referencia: README del proveedor https://github.com/openscriptures/morphhb/blob/6a5db284c715c18b239422e57bb89684e6a19f00/README.md y archivos OSIS admitidos.

Identidad interna determinista SHA-256 de tuplas: edición fijada, referencia OSIS para unidad y posición base cero de palabra directa para token. IDs del proveedor se conservan aparte, con control de duplicados; no se usa Strong como identidad. Orden canónico operativo Gen/Dan para esta muestra, no declaración de canon. Segmentos no consumen posición de palabra; se retiene su orden de evento. Formas originales y barras OSHB intactas, sin normalización. Texto de unidad derivado con espacios de lectura, no reconstrucción exacta de XML. El idioma se toma únicamente de prefijos H/A de códigos OSHB, no de la grafía; códigos ausentes o no reconocidos quedan como null en el registro intermedio y fuera del registro compatible con contratos. No interpretar rasgos.

Se amplía el parser para lecturas directas x-qere dentro de notas de variante, sin copiar notas libres, catchWord ni otros metadatos. Las lecturas alternativas tienen IDs independientes y no se agregan al recuento principal. Solo se vincula automáticamente una lectura a la palabra inmediatamente precedente si está marcada x-ketiv; en otro caso el anclaje queda null. La estructura de nota sigue contabilizada como pendiente por contener componentes no proyectados. Las variantes complejas y elementos no reconocidos quedan pendientes de auditoría; no afirmar cobertura completa. No se convierten códigos léxicos ni se crea análisis morfológico.
