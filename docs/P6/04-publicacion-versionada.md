# P6.4. Publicación versionada
Base 420f549b3c84ae9145c6addad76cab4bb84e3f89; despliegue P6.3 45772552162 exitoso. Rama feature/p6.4-versioned-publication.
Se implementa un registro explícito de snapshots aprobados, separado del catálogo inicial y de los borradores privados. El registro público nace vacío; las rutas individuales consultan exclusivamente el registro validado, con render de cuerpos en texto escapado y relaciones solo si existe snapshot admitido. Los borradores deben mantenerse fuera del repositorio público; .gitignore es una precaución, no una barrera de seguridad ni elimina archivos ya versionados. No se habilita carga automática de borradores.
El contrato exige coincidencia de estudio y versión, revisión aprobada vinculada, controles críticos conformes (P6.1), relaciones válidas (P6.3), evidencia verificada y autorizada, admisión independiente por cada BIB/REC con licencia, atribución y autorización documentadas. Las secciones deben estar revisadas o justificadamente no aplicables; S01/S02/S17/S19/S20 se exigen revisadas como mínimo conservador. Los cuerpos se vinculan por ID de sección, se rechazan cuerpos huérfanos, se usa texto plano sin HTML ejecutable. SHA-256 sobre JSON canónico detecta modificaciones accidentales; no es firma ni acredita aprobación humana. El registro es append-only por API, cadena de versiones creciente y copia independiente; Git conserva historial. La revisión y admisión reales siguen siendo responsabilidad humana.
P7 deberá conectar un inventario de fuentes, autores y permisos revisados: las listas de admisión actuales están vacías y bloquean cualquier publicación real. No se cambia el catálogo ni el índice de búsqueda inicial (solo metadatos planificados), ni se habilita la indexación del cuerpo aprobado; su ampliación requiere adaptar estados públicos, índice y validadores de catálogo cuando existan fuentes admitidas. El componente de publicación ya está conectado a la ruta individual, pero no se puede publicar un estudio real en esta fase sin esa dependencia. El historial es estructural, no una interfaz de administración ni archivo histórico navegable. La función heredada publicationEnabled de P6.1 se mantiene falsa para no abrir una segunda vía.
Doce pruebas sintéticas y controles de salida inicial, CI pendiente. Casos sintéticos exclusivamente en tests. VAL-04/06/11/12/14 estructurales; no certifican licencias ni revisión documental real. Pendientes manuales anteriores conservados. P6.5 no se inicia.
